INTRODUCTION                                    *omarchy-plugin-dev-introduction*

omarchy-plugin-dev.nvim detects schema-version-1 Omarchy shell plugin manifests
and provides explicit Overseer tasks, native LSP setup, project-local maps,
and a small dashboard. It stays inactive for unrelated QML projects and never
runs a project command merely because a buffer opened.

==============================================================================
REQUIREMENTS                                    *omarchy-plugin-dev-requirements*

- Neovim 0.11 or newer
- stevearc/overseer.nvim
- omarchy and Qt 6 qmllint for Check
- journalctl for shell logs
- jq and rsync for staged deployment
- Qt qmlls for LSP features

On Arch: >bash
  sudo pacman -S qt6-declarative
<
The plugin also recognizes the Mason qmlls package.

==============================================================================
INITIALIZATION                                *omarchy-plugin-dev-initialization*

                                                               *:OmaDevInit*
:OmaDevInit
    Validate the detected project with the installed Omarchy validator and
    add the hidden task directory to .gitignore before creating:
        .omarchy-plugin-dev/tasks.json

    If an executable ./scripts/test or ./tests/all.sh exists, choose whether
    to configure it. Otherwise an empty tasks object is created and opened
    for editing. Initialization never invents a missing test command.

:OmaDevInit!
    Explicitly approve replacing an existing tasks.json. Without !, an
    existing file is preserved and an overwrite choice is shown.

Schema version 1 contains a "tasks" object. Each task contains a non-empty
"command" argument array and may contain a string "description". Commands
always run at the detected project root. Shell command strings are invalid.
The "test" task supplies the Test action. No project-local Lua is loaded.

==============================================================================
COMMANDS                                            *omarchy-plugin-dev-commands*

                                                                   *:OmaDev*
:OmaDev
    Open the project dashboard.

                                                               *:OmaDevTest*
:OmaDevTest
    Run the project-defined "test" argv. Missing configuration is a non-error
    explanation that points to initialization.

                                                          *:OmaDevHotReload*
:OmaDevHotReload
    Check, stage, validate, and deploy the project, then restart the Omarchy
    shell exactly once.

                                                            *:OmaDevRebuild*
:OmaDevRebuild
    Check, run the configured test, deploy, then restart the shell exactly
    once. A missing test task or unavailable test executable stops the
    default workflow. A complete tasks.rebuild override owns its test policy.

                                                             *:OmaDevHealth*
:OmaDevHealth
    Run the standard `checkhealth omarchy-plugin-dev` report.

==============================================================================
MAPPINGS                                            *omarchy-plugin-dev-mappings*

Defaults exist only in QML buffers inside detected Omarchy projects:

  <C-b>            Check, deploy, and restart once
  <C-S-b>          Test, deploy, and restart once
  <localleader>t   Test
  <localleader>o   Dashboard

Existing mappings are preserved. The plugin does not change maplocalleader.
Every mapping is buffer-local and has a human-readable description.

==============================================================================
CONFIGURATION                                  *omarchy-plugin-dev-configuration*

Call setup through a plugin manager's opts or directly: >lua
  require("omarchy_plugin_dev").setup({
    diagnostics = {
      virtual_text = false,
    },
    mappings = {
      enabled = true,
      hot_reload = "<C-b>",
      rebuild = "<C-S-b>",
      test = false,
    },
    executables = {
      jq = "jq",
      omarchy = "omarchy",
      qmllint = "auto",
      qml_language_server = "auto",
      rsync = "rsync",
    },
    notify = true,
    log_level = vim.log.levels.INFO,
  })
<
Set mappings to false, mappings.enabled to false, or an individual mapping to
false to disable defaults. Executable names, QML import paths, notifications,
and Overseer task definitions are configurable. Setup and commands remain
available without mappings.

The qmllint value "auto" prefers /usr/lib/qt6/bin/qmllint and accepts a PATH
candidate only when it reports Qt 6 or newer. An explicit override is honored
as-is. The dashboard shows the selected path and version.

The QML language server prefers the system Qt qmlls, then PATH and Mason. A
generic qmlls attached by another Neovim integration is detached only from
detected Omarchy Plugin buffers. The project-aware server resolves qs.*
imports through a generated cache bridge; it does not write .qmlls.ini or
other tooling files into the plugin repository.

Inline diagnostic text is disabled for this server by default because qmlls
cannot fully model runtime-injected Omarchy objects. Underlines, signs,
diagnostic pickers, and the Overseer lint quickfix list remain available. Set
diagnostics.virtual_text=true to restore it, or diagnostics=false to inherit
Neovim's global diagnostic display.

==============================================================================
BUILD SEMANTICS                                        *omarchy-plugin-dev-build*

There is no compile step for ordinary Omarchy QML plugins. Both build mappings
use an Overseer orchestrator and expose omarchy restart shell as their final
step. This prevents QML components and IPC handlers from surviving from the
previous plugin generation.

Deployment never runs omarchy plugin update. A symlink from the installed
plugin to the project is preserved, and a project opened directly inside its
installed checkout needs no copy. Otherwise deployment synchronizes a clean
staged copy. A separate git-managed installation is refused rather than
modified, because doing so would dirty the checkout and break normal updates.

==============================================================================
TROUBLESHOOTING                              *omarchy-plugin-dev-troubleshooting*

Run :OmaDevHealth, or invoke the native command directly: >vim
  :checkhealth omarchy-plugin-dev
<
The report checks the Neovim version, Overseer, exact executable paths, the
Qt 6 qmllint version, and the QML language server.
